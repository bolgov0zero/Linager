# Агент для Windows (beta)

Агент работает на Windows 10 / 11 и Windows Server 2016 и новее (x64) и подключается к серверу Linager так же, как Linux-агент. **Сервер остаётся на Linux.** Windows-агент пока в beta: в нём только модули, которые прямо ложатся на Windows.

## Что работает

| Вкладка | Что делает в Windows |
|---|---|
| Метрики | процессор, память, подкачка, диски (каждый том с файловой системой), сетевые адаптеры и скорость, время работы, процессы, «нужна перезагрузка» (Windows Update). Средней нагрузки (load average) в Windows нет: показывается 0. |
| Терминал | PowerShell (cmd.exe, если его нет) в псевдоконсоли (ConPTY, Windows 10 1809 / Server 2019 и новее). Оболочка работает от имени **SYSTEM**, с полным доступом агента, как root-оболочка в Linux. Всё пишется в журнал аудита. |
| Службы | список из диспетчера служб (SCM): запуск, остановка, перезапуск, тип запуска (включить = автоматически, отключить = отключена). Подтверждение требуют сам агент, удалённый рабочий стол, WinRM, sshd, службы RPC, DHCP, DNS и файрвола. Автоматическая служба, которая остановилась с ошибкой, считается сбойной. |
| Процессы | список с процессором, памятью, пользователем и командной строкой; «завершить» (в Windows один способ завершить процесс, поэтому «завершить» и «убить» делают одно и то же). Системные процессы (csrss, lsass, services, wininit, winlogon, smss, System) отклоняются. |
| Журналы | журналы событий Windows в реальном времени: по умолчанию System и Application; в поле «служба» можно указать классический журнал (`Security`, `Setup`), журнал событий приложений (`Microsoft-Windows-TaskScheduler/Operational`) или имя источника (например `Service Control Manager`). «Ядро» показывает источники ядра. Приоритет переводится в уровень (ошибка, предупреждение, информация). |
| Файлы | файловый менеджер. Верх дерева это список дисков, пути выглядят как `/C:/Users/x`. Владелец и группа не показываются, права из панели менять нельзя (в Windows ACL). Корни дисков, `C:\Windows`, `C:\Program Files`, `C:\ProgramData`, `C:\Users` нельзя переименовать, удалить или заменить. |
| Перезагрузка | `shutdown /r`, с подтверждением. |

В Windows недоступно (вкладки скрыты): обновления (apt), очистка диска, сеть, файрвол, безопасность (fail2ban, ключи), пользователи, Docker.

## Установка

Скачайте `linager_windows_amd64.msi` из релиза (beta-релиз имеет тег `vX.Y.Z-beta.N`; сверьте с `SHA256SUMS`) и установите из командной строки с правами администратора:

```powershell
msiexec /i linager_windows_amd64.msi /qn SERVER=panel.example.com:9443
```

`SERVER` это порт агентов сервера (`хост:порт`). `FINGERPRINT=SHA256:...` необязателен: с ним агент доверяет только сертификату с этим отпечатком; без него привязку защищает проверочный код (см. ниже). Пакет ставит `C:\Program Files\Linager\linager.exe`, регистрирует службу **Linager Agent** (`LinagerAgent`, автозапуск, работает от SYSTEM, после сбоя запускается снова) и запускает её.

### Привязка
1. В панели откройте «Добавить сервер», вкладка «Подтверждения»: узел появится там через несколько секунд после запуска службы.
2. На Windows-машине прочитайте ключ и проверочный код (доступно только администраторам):

   ```powershell
   Get-Content C:\ProgramData\Linager\agent\enroll.txt
   ```

3. Введите ключ («Ключ подтверждения») и **убедитесь, что проверочный код совпадает**: он связывает ключ с сертификатом, который увидел агент, и защищает привязку от посредника, когда отпечаток не задан. Подтвердите.

То же из консоли: `& "C:\Program Files\Linager\linager.exe" agent enroll --server panel.example.com:9443`. Служба замечает новую привязку в течение 10 секунд.

## Файлы, журнал и удаление
- `C:\ProgramData\Linager\agent\` ключи и состояние; `C:\ProgramData\Linager\agent.yaml` (модули, необязателен, формат как в Linux: `modules:` со значениями `true` / `false`); `C:\ProgramData\Linager\agent.log` журнал (файл больше 5 МБ переименовывается в `agent.log.1`). Папка `C:\ProgramData\Linager` открыта только SYSTEM и администраторам: это аналог прав 600 у Linux-агента.
- `linager.exe agent status` показывает версию, сервер и состояние службы.
- После правки `agent.yaml` перезапустите службу: `Restart-Service LinagerAgent`.
- Удаление: `msiexec /x linager_windows_amd64.msi /qn`. Ключи, журнал и адрес сервера остаются; чтобы убрать и их, удалите `C:\ProgramData\Linager` и раздел `HKLM\SOFTWARE\Linager`. «Удалить сервер» в панели заставляет агента убрать свою привязку и службу.

## Обновление
Из панели, как у Linux-агента: страница «Обновления» (один агент, выбранные или все). Сервер отдаёт агенту подписанный `linager_windows_amd64.exe` своего релиза (тот же файл, что ставит MSI). Агент проверяет подпись манифеста и контрольную сумму, сохраняет работающий exe как `C:\ProgramData\Linager\agent\linager.prev.exe`, отодвигает запущенный файл (Windows разрешает переименовать работающую программу, но не перезаписать), ставит новый на его место и перезапускает службу. Стадии те же, что в Linux (загрузка, проверка, резерв, замена, перезапуск, офлайн, повторное подключение, подтверждение).

**Откат.** Перед перезапуском агент создаёт разовую задачу планировщика Windows `LinagerAgentRollback` (от SYSTEM, примерно через 70 секунд). Новая версия подтверждает себя первым подключением к серверу и удаляет задачу. Если этого не произошло (не запустилась или не достучалась до сервера), задача запускает СТАРЫЙ exe: он останавливает службу, возвращает старый файл и снова запускает службу. Вручную: `linager.exe agent update`, `linager.exe agent status`.

**Агенты beta.1–beta.3 из панели обновить нельзя** (в них нет нужного кода): в таблице стоит «новый MSI X». Один раз поставьте MSI версии `0.3.0-beta.4` или новее, после этого панель обновляет агент. Та же пометка появляется, если в релизе нет Windows-файла. В списке программ Windows (продукт MSI) после обновления из панели остаётся версия MSI: на работу агента это не влияет, следующий MSI ставится поверх как обычно. Сервер того же релиза нужно обновить раньше, как и для Linux-агентов.

## Ограничения beta
- Только x64. Агент обновляется из панели начиная с `0.3.0-beta.4`; откат неудачного обновления проверен на Windows-раннере и на одной тестовой машине. Exe и MSI не подписаны сертификатом подписи кода, поэтому SmartScreen или антивирус могут предупреждать.
- Проверено: код собирается и тестируется на Windows-раннере GitHub Actions (метрики, службы, процессы, файлы, терминал, установка и удаление MSI). На реальном парке не проверялось.
- Windows 11 в реестре называется «Windows 10»; агент различает их по номеру сборки (22000 и выше).
